# Internationalisation

All user-facing text is a message key (ADR 0020).

## In specs and manifests
```yaml
title: { t: customers.title }
emptyState: { t: customers.empty, args: { filter: $filter } }
```
- Type `Text = { t: key, args? }`. Plain strings pass `spec:check` in drafts and fail on publish.
- Keys are relative to the app (`customers.title` -> `<app>:customers.title`).

## Catalogs
- `apps/<id>/i18n/<locale>.yaml`, ICU MessageFormat (plurals, select). Also `@platform/ui` and platform catalogs.
- The default locale (deployment setting, `en` initially) must contain every key; `spec:check` reports missing ones.

## Runtime
- Locale: user profile, else deployment default. Fallback: default locale, then the key itself.
- `GetPage` sends the messages the spec uses; the client formats with `intl-messageformat`. Cache varies by locale.
- Dates, numbers, money and units: `Intl` with the user's locale and timezone.
- Errors carry `code` + message key. Emails and job output: `ctx.i18n.t(key, args, locale?)`.

- Translated record data (one product name per language).
